## Design Specificity Verdict

**LLM assessment:** Authored, but not fully distilled. The warm paper, serif editorial hierarchy, restrained rust signal, repository-first thesis, and Suricata vocabulary belong to this product. The weak layer is composition: Architecture becomes a dark technical console inside an editorial document, and several routes repeat the same information through simultaneous controls and summaries. It avoids bento, glass, glow, and pill clichés, but still feels like a styled specification rather than a truly edited field guide.

The high-end opportunity is not luxury effects. It is stronger authorship: fewer visible decisions, a sharper sequence, one unmistakable hero artifact per route, and more deliberate transitions between overview, detail, and handoff.

**Deterministic scan:** The detector returned one advisory: `codex-grid-background` at `app/globals.css:146`. This is a contextual false positive because `.map-grid` is confined to the diagram canvas, is `aria-hidden`, and the design brief explicitly permits functional diagram grids. Source inspection additionally found 37 raw color literals after the root token block despite DESIGN.md saying raw values belong in tokens, plus a global reduced-motion rule that collapses every transition to `.01ms`; these are design-system debts, not the reason the product feels weak.

**Visual overlays:** No reliable overlay is available. Browser discovery returned `No browser is available` and an empty browser list, so injection and fresh viewport screenshots were not possible in the isolated assessments. HTTP and source/render-structure evidence were used as the fallback.

## Overall Impression

The product idea is much stronger than the current information hierarchy. It looks thoughtful and trustworthy, but it asks the reader to process too many parallel explanations. The single biggest opportunity is ruthless editorial reduction: each route should have one dominant artifact and one next action.

## What's Working

- Provenance is integrated into the reading experience. Revision, coverage, fixture/live status, and limitations are treated as product information rather than fine print.
- The visual world is coherent and appropriately human: warm neutral paper, near-black ink, IBM Plex Serif/Sans, restrained signal color, and hairlines instead of dashboard cards.
- The product boundary is excellent. Trust never masquerades as vulnerability scoring, and Lachesis is consistently positioned as the source/symbol continuation.

## Priority Issues

### [P1] Start repeats orientation instead of sequencing it

**Why it matters:** The page shows two map actions, six macro-path links, the same two actions again, and three more ways in. “Follow a packet” appears repeatedly, so the supposed recommendation reads as one option among many.

**Fix:** Reduce Start to repository identity and thesis, one dominant simplified map, one primary “Follow a packet” continuation, and one quieter Architecture link. Remove the repeated Start-with/action block or merge it into the map introduction.

**Suggested command:** `$impeccable distill`

### [P1] Architecture exposes every disclosure layer at once

**Why it matters:** Map, toolbar, inspector, ordered summary, directory, embed controls, next section, and evidence note compete in one document. Mobile merely serializes all of them into a long page. The map never gets to be the clear moment of comprehension.

**Fix:** Make the map plus stable inspector primary on desktop. Move the full directory and detailed evidence into region chapters or a disclosure. On mobile, show the ordered topology and route selection directly to the chapter; do not repeat node list, inspector, summary, and directory.

**Suggested command:** `$impeccable distill`

### [P1] Flows has competing navigation models

**Why it matters:** Branch choices, a five-step path map, the same five-step stepper, Previous/Next, Lachesis, and “all steps” are visible together. The user must learn the UI before learning the packet path.

**Fix:** Choose one canonical stepper with Previous/Next. Keep the full path as a quiet progress overview and make the linear transcript a fallback/disclosure, not a third co-equal controller.

**Suggested command:** `$impeccable clarify`

### [P2] Mobile compresses trust-critical context

**Why it matters:** Product mark, repository, revision, and snapshot state share one 64px row with percentage caps and hidden overflow. The most important maintainer facts are the first to become abbreviated.

**Fix:** Give repository identity and snapshot truth two lines on mobile. Reduce or move the product wordmark, retain the full status label, and keep revision disclosure reachable without ellipsis ambiguity.

**Suggested command:** `$impeccable adapt`

### [P2] Embed is a full application page, not a distribution artifact

**Why it matters:** Reusing the entire MapClient brings inspector, relationship summary, and directory into README-sized contexts. The embedded orientation becomes tall and self-referential.

**Fix:** Define an embed-specific contract: repository/revision/status, one bounded topology, one caption, and one “Open full guide” action. Remove inspector, directory, authoring copy, and embed-within-embed controls.

**Suggested command:** `$impeccable distill`

## Persona Red Flags

- **Jordan, first-time OSS contributor:** repeated “Follow a packet,” Architecture choices, map stages, and “ways in” weaken the first decision. Architecture then asks Jordan to understand map level, inspector, summary, and directory at once.
- **Alex, experienced contributor:** deep links help, but long duplicated sections slow direct scanning. Flow controls and three representations of Architecture regions add interaction tax without adding evidence.
- **Casey, mobile contributor:** Architecture becomes several consecutive lists, Trust opens all eight domains, and the embed becomes a long document. Content reflows, but the task does not become shorter or more thumb-friendly.
- **Mina, OSS maintainer:** provenance copy is excellent, but mobile truncation can hide repository/revision/status. A generic footer handoff without selected context makes the otherwise precise Lachesis contract feel less disciplined.

## Minor Observations

- The Design Map mark has more visual priority than the repository on mobile; that hierarchy is backwards for a repository-first product.
- Repeated uppercase mono labels collectively recreate tool chrome even though each one is restrained.
- Trust-family bordered tokens read like dashboard tags when repeated across eight expanded domains.
- The dark map surface is defensible, but its grid and axes need to communicate topology rather than atmosphere.
- Consolidate the 37 post-token raw colors into semantic map/state tokens during the redesign; do not treat that cleanup as the redesign itself.
- Replace the global reduced-motion kill switch with component-level no-travel states that preserve immediate state feedback.

## Questions to Consider

- If Start could offer only one primary action, should it be “Follow a packet” or “Open Architecture”?
- Should Architecture optimize first for a visual map moment or for a documentation-first ordered topology?
- Is the embed meant to be a compact README preview or a fully interactive mini-application?
- Do you want the next pass to remove duplication across all routes, or rebuild Start and Architecture first?
